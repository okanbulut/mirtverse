Which IRT model?

Start from what one item score looks like, answer a question or two, and end at a model and the line of R code that fits it. When in doubt, let select_model() compare the candidates for you.

Every path ends in the same call
library(mirtverse)
mod <- mirt(data, 1, itemtype = "2PL")
interpret(mod) explains the result

Then think about the structure Each question adds one argument or one function

More than one trait?

Check local dependence first, then fit two or more factors.

gg_q3(mod)mirt(data, 2)mirt.model("F1 = 1-5 ...")

Items in clusters?

Testlets, shared passages or scenarios: a general factor plus specific ones.

bfactor(data, specific)

Groups to compare?

Check items for DIF, then link the groups on one scale.

dif(mod, group)multipleGroup(data, 1, group)

Item features matter?

Explain difficulty with item properties (LLTM, explanatory IRT).

predict_difficulty()eirm::eirm()mixedmirt()

Response times too?

Model speed with ability and flag unusual timing.

fit_rt(mod, rt)

Classes, not a continuum?

Mastery groups or latent profiles instead of a trait.

mdirt(data, 2)

Before you trust the model

  • glance(mod) overall fit (M2, RMSEA, CFI)
  • gg_itemfit(mod) items that misfit
  • gg_trace(mod) curves that look strange
  • interpret(mod) a plain-language summary

A simpler model that fits is easier to explain. Move to a richer one only when the fit checks or the purpose of the test call for it.
